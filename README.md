# 365freebonus

A restrained purple and champagne-gold brand directory with an animated 3D-style cover, matching avatar, multilingual browsing, search, filters, saved brands and an independent admin dashboard.

The included brands are fictional demonstration content. The application contains no payment, wagering or bonus redemption system.

## Run locally

Use Node.js 24 or newer.

```sh
npm ci
npm run dev
```

The public directory works without admin configuration. The dashboard requires administrator login at `/login`. The content database is stored in `.data/directory.sqlite` by default.

## Administrator configuration

Run `node scripts/create-admin.mjs` locally to generate a random password, scrypt password hash and session secret. Store the returned environment values in your deployment provider, and keep the password private. Never commit the output.

| Variable | Purpose |
| --- | --- |
| `ADMIN_USERNAME` | Administrator username, normally `admin` |
| `ADMIN_PATH` | Optional dashboard path, one lowercase URL segment with a leading slash. Defaults to `/admin`. |
| `ADMIN_PASSWORD_HASH` | `scrypt$saltHex$hashHex`; 64-byte scrypt key |
| `SESSION_SECRET` | A random secret of at least 32 characters |
| `APP_URL` | Exact canonical origin for CSRF validation |
| `DATA_DIR` | Database directory; `/data` on Railway |
| `PORT` | HTTP port, normally `3000` |

If using `.env.local`, escape each `$` in the password hash as `\$` because Next.js expands dotenv variables. Railway variables store the raw value without escaping. `.env*`, database files, dependencies and generated builds are excluded from source control. Admin writes fail closed when authentication has not been configured.

After signing in, use **更改密码** in the dashboard sidebar. Enter the current password, then a new password of 12–128 characters twice. A successful change signs out every device and requires a new login. Only a salted scrypt hash is stored in the private persistent database, and it takes precedence over the bootstrap `ADMIN_PASSWORD_HASH` after the first change. Deployments do not reset it. Keep `SESSION_SECRET` unchanged so saved Telegram credentials remain readable. Recovery of a forgotten password requires an authenticated infrastructure operator; there is no public password-reset endpoint.

## Railway

The Dockerfile builds a standalone Next.js server with Node.js 24. Connect this repository to one Railway service, mount a persistent volume at `/data`, set `APP_URL` to the Railway or custom domain, and configure the admin variables. Use a single service replica with SQLite. `railway.json` configures `/api/health` and restart behavior. GitHub pushes to the connected branch trigger deployment.

The volume keeps brands, settings, sessions and login-rate limits across restarts and deployments. Back up the SQLite database using SQLite's online backup API before moving or replacing the volume.

## Content management

- **安全笔记** stores private editable records behind the administrator login and an independent 6–12 digit PIN. First use requires the current administrator password to set the PIN. Titles and note contents are encrypted in the private `/data` database. PIN unlock is remembered in the same browser across section changes, tab switches, refreshes and a later administrator login using the same credentials. It locks after 12 hours without real administrator activity. Visible notes are cleared when the tab hides or the section unmounts and are restored after checking server authorization. Passive status queries and background polling do not extend the timeout. Every notes request still requires an active administrator login; signing out, locking manually, or changing the administrator password revokes the remembered unlock. PIN attempts are rate limited, and changing the PIN revokes every notes unlock. Keep the PIN safe: there is no bypass reset. The former website auto-login menu, API and worker have been removed; migration 13 removed its saved account configuration; migration 14 replaces only temporary unlock sessions and preserves the PIN, encrypted notes, brands, settings and Telegram data.

- Migration 19 preserves settings, notes/PIN and existing queues and adds a persistent relay media-identity ledger. Deduplication uses Telegram file identity, file-byte SHA-256 and metadata-independent decoded photo pixels, independent of caption or source. Migration 24 scopes those identities to Asia/Kuala_Lumpur calendar dates, preserving same-day protection across restarts and configuration changes while allowing new source posts with the same media the next day. Recompressed/edited pictures are not guaranteed to match; fuzzy matching is intentionally avoided so similar advertisements remain distinct. Pending account media is capped at 64 MiB/128 jobs and removed after terminal delivery; queues apply backpressure instead of consuming source cursors when full. Ambiguous/in-flight jobs remain terminal and are never automatically resent.
- Migration 23 removes the album-level uniqueness restriction while preserving all jobs, message IDs, media identities, settings and notes/PIN. Each different captioned photo/video/GIF in an album is eligible independently; identical captions never suppress different media. The same source message or known media identity remains deduplicated. Text-only messages and media without a caption remain excluded. Existing skipped history is not replayed.
- Migration 24 preserves all media keys and owners with a (Malaysia day, media key) primary key; legacy sent keys use sent_at and other keys use queued_at, with a further conservative lease-day reservation for sending jobs. No source cursors, messages, settings, notes/PIN or job statuses are reset. New media is checked again against its actual dispatch day, including already-prepared media and aliases. Requests starting within 60 seconds of midnight temporarily reserve the next day as well; that reservation is released only for a trustworthy result completed before midnight, while ambiguous/in-flight requests retain it. Completion/cancellation/expiry protects the current day without reactivating old unknown jobs or cancelling sent posts. This is calendar-day deduplication, not a rolling 24-hour interval or a scheduled replay of old content. Historical unknown jobs have no confirmed delivery timestamp, so their original receipt date is used rather than asserting an actual send day.
- Migration 20 widens the relay queue to include video while preserving every job ID, binary payload, dedup key and AUTOINCREMENT high-water mark. Attached captioned MP4 videos use sendVideo; other attached video formats read through the personal account retain the original file via sendDocument with the same caption and fixed buttons. Personal video uploads are capped at 50 MiB and 40 seconds. Bot-source videos reuse their Bot API file ID directly, so the 20 MiB getFile download limit does not prevent an existing video from being relayed. Photos continue using both file identity and byte/pixel hashes; text-only posts, previews and captionless media are skipped.
- Migration 21 persists explicit caption entities. Relay captions preserve original Unicode text, whitespace, line breaks, styles and custom-emoji document IDs; visible URLs are rewritten while hidden links retain their label and point to the website. UTF-16 offsets are recalculated after URL changes. Every media path sends caption_entities; it never silently retries without custom emojis. Telegram may restrict custom emoji usage based on bot entitlement and destination type. Rejected custom-emoji posts and successful responses missing expected IDs surface safe backend warnings without automatic duplicate sends. Overlength captions are stopped rather than posted with clipped text. Legacy pending jobs whose original entities were never captured remain stored with an unknown-metadata sentinel and stop safely; this update does not resend already-forwarded posts or clear image deduplication.
- Custom emoji identifiers use nonzero signed int64, preserved as decimal strings with BigInt validation (including negative IDs). The receiver compares source custom-emoji counts with prepared metadata and stops the job if artwork metadata is lost. Private startup diagnostics contain only bounded counts/statuses/timestamps from at most 200 jobs; an enabled, connected personal receiver may read up to three selected sources and five recent messages each to count metadata only. This read-only sample honors account leases/backoff and changes no source cursor, queue or session; no captions, account/channel IDs, custom-emoji IDs or credentials enter diagnostic logs. Telegram response checks log only aggregate counts, with successful samples limited to five per process.
- A bounded private qualification audit may read the connected account's own status and owned-bot list to classify documented custom-emoji prerequisites. It returns only an operational qualification enum plus destination type, never profile fields or bot/username lists. It respects the same lease/backoff rules and does not purchase subscriptions, send messages, or change account configuration.
- Migration 22 adds durable caption-edit attempt/outcome fields without changing settings, notes/PIN, queued media or duplicate identities. Initial sends always contain rewritten website links and the three fixed owner buttons. Their returned captions, custom-emoji metadata, clickable targets and buttons are checked. A confirmed sent post with a known mismatch may receive one `editMessageCaption` using its existing destination message ID; recent mismatches are eligible only within 24 hours and the current verified destination/configuration generation. The attempt is persisted before the request and shares the send lease, so restarts, ambiguous responses and rate limits cannot create repeated edits or duplicate media posts. Edits also obey Telegram custom-emoji restrictions and do not guarantee entitlement-dependent artwork. Private edit diagnostics expose only outcomes, booleans and counts.
- If that Bot edit is rejected or still loses custom emojis on a delivered post with saved custom-emoji metadata, the connected personal account may perform one additional caption-only edit of the same verified channel post. This requires its own Premium subscription and current channel creator/edit-messages rights, a direct non-forwarded/non-inline post, unchanged stored caption, safe owner links, the three exact existing buttons, and valid account plus global relay leases. MTProto receives only the original caption/entities, with no media or reply-markup replacement and no automatic retry of the edit. A fresh read must confirm the same media identity, caption, custom-emoji IDs/positions, safe links and fixed keyboard before reporting success. Durable account-stage outcomes prevent repeated edits across restarts; unavailable account leases/backoff allow only three bounded preflight waits. No subscription is purchased and no channel/account permissions are changed.
- A post preflight may perform up to three read-only checks within the existing deadline before any personal edit is submitted. A preflight-only `account_invalid` record can receive one separately leased read-only recheck; only a fully verified post may enter `account_revalidated` and the original edit flow. Migration 25 persists a per-post recheck counter before that recovery so restarts cannot reopen it indefinitely. Persistent mismatches after recovery are final, and an actual edit attempt is never replayed. Diagnostic logs record only fixed reasons, persistence booleans and counts; the independent blocked-post audit never rearms or edits messages.
- After a personal edit succeeds, confirmation may perform up to three read-only checks within the same absolute deadline. Temporary stale reads or transient read failures cannot immediately turn an otherwise successful edit into a permanent unconfirmed result. Every confirmation revalidates account and target permission, source/configuration and both leases; Telegram rate limits and changed authority stop verification without repeating the edit. The dashboard retains unresolved errors from the current relay revision even when a newer post succeeds, so a delivered photo is not mistaken for proof that every caption edit succeeded.
